# pawn-wars
Пешечные бои

[Играть в браузере](https://nerevar.github.io/pawn-wars/)

## Выбор хода компьютером

При alpha-beta-отсечении поиск иногда возвращает границу оценки вместо точного
значения. Из-за этого худший ход мог попасть в случайный выбор среди лучших.
Теперь равные оценки ходов в корне перепроверяются с полным окном поиска.
Случайный выбор между действительно равноценными ходами сохраняется.
Уровни 0–4 сохраняют прежние глубины и оценки;
«Очень сложный» использует `bestV1` на глубине 5.

Факторы `mediumAdjacentThreat` и `opponentBlocked`, чья разность оценок белых
и чёрных всегда равна нулю, удалены из оценки и подбора весов. Старые JSON-файлы
весов совместимы: эти два имени игнорируются, остальные неизвестные имена
по-прежнему вызывают ошибку.

## Логирование поиска

Подробное дерево поиска по умолчанию выключено. Флажок «Логирование поиска»
в инженерном меню включает его для отладки; параметр `searchLogging=1`
сохраняет настройку в ссылке на игру. Обычный поиск не строит дерево логов.

## Супер сложный

Новый уровень 5 использует ту же оценку `bestV1`. На любом устройстве он
обязательно завершает поиск на глубине 6. Затем пробует глубины 7 и 8,
пока хватает общего бюджета 500 мс. Если очередная итерация прервалась,
выбирается ход последней полностью рассчитанной глубины.

500 мс — мягкий бюджет: обязательная глубина 6 может занять больше времени.
На медленном устройстве соперник думает дольше, но не опускается до глубины 5.
Более глубокий эвристический поиск не гарантирует лучший ход в каждой позиции;
силу уровня нужно проверять парными турнирами с перестановкой цветов.
Поиск остаётся синхронным, без Web Workers.

Кеш позиций ограничен 50 000 записями и живёт только в пределах одного хода.
В нём различаются точная оценка и границы после alpha-beta-отсечения.
Пользовательские функции оценки, зависящие от пути, не кешируются, пока
стратегия явно не задаст `transpositionSafe: true`.

Третий аргумент `findBestMove(strategy, getAllMoves, options)` позволяет
переопределять `minDepth`, `maxDepth`, `maxTimeMs`, `maxNodes`,
`useTranspositionTable` и `maxTableEntries`. Лимиты времени и узлов действуют
только после обязательной `minDepth`; по умолчанию поиск фиксирован на
`strategy.depth`. `now` позволяет подставить часы в тестах.
`debug.stats` и `result.stats` содержат завершённую глубину, число узлов,
попадания в кеш, время итераций и причину остановки. Подробное дерево
независимо управляется флажком логирования.

## Проверка

```sh
node --test test/search.test.js test/transposition_table.test.js test/adaptive_search.test.js test/difficulty_ui.test.js
```

Синтетические позиции проверяют результат полного перебора minimax, ложные
и настоящие равенства, оба цвета, взятие на проходе, превращение пешки,
порядок перебора ходов, кеш, обязательную глубину на медленных часах,
остановку внутри итерации, восстановление доски и логов, выбор нового
уровня и сохранение настроек в URL.

В прежнем наборе `node test/test_runner.js --runs 10` остаётся известный
провал стратегии `medium`: ход `d6` после `1. d4 h6 2. f3 f6 3. g3 e5
4. e3 f5 5. c3 g6 6. dxe5 b5 7. b3`. Он воспроизводится и на исходной версии.
